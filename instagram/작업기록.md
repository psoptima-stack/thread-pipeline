## 3. 설계상 꼭 기억할 것 세 가지

### ① 인스타 API는 파일 업로드를 안 받는다
**공개된 https 이미지 주소**만 받습니다. 그래서 카드를 저장소에 커밋해서
`raw.githubusercontent.com` 주소로 넘깁니다. 저장소가 공개라 가능한 방식입니다.
워크플로 순서가 **카드 생성 → 커밋·푸시 → 게시** 인 이유가 이것입니다.
브랜치 주소는 캐시가 남을 수 있어 **커밋 해시로 고정**해서 넘깁니다.

### ② PNG는 거부당한다
게시 API는 JPEG만 받습니다. `make_cards.py` 기본 출력이 jpg입니다.
(`subsampling=0` 으로 저장해야 글자가 안 뭉개집니다)
`--format png` 는 미리보기용이며, cards 아래 png는 `.gitignore` 처리했습니다.

### ③ 캐러셀은 최대 10장
넘으면 앞 10장만 올라가고 경고를 찍습니다. 현재 원고는 5장 내외라 여유 있습니다.

→ `date` 에 `2026-08-18` 입력 → 실행 → 로그 확인

### ④ 토큰 자동 갱신 — A안 채택, 워크플로 작성 완료

`.github/workflows/instagram-token-refresh.yml`
매달 1일 12:00 KST 에 토큰을 갱신해 `IG_ACCESS_TOKEN` Secret 을 덮어씁니다.
갱신할 때마다 다시 60일이 되므로 만료될 일이 없습니다.

**동작하려면 PAT 하나가 더 필요합니다.** GitHub 기본 토큰으로는 Secret 을 못 씁니다.

1. https://github.com/settings/personal-access-tokens/new (Fine-grained)
2. Repository access → **Only select repositories** → `thread-pipeline`
3. Permissions → Repository permissions → **Secrets: Read and write**
4. 만료: 1년 등으로 설정 후 생성 → 토큰 복사
5. 저장소 Secret 에 **`SECRETS_ADMIN_PAT`** 이름으로 등록

> PAT 자체도 만료됩니다. 만료되면 갱신 워크플로가 실패하면서
> GitHub 이 이메일로 알려주므로, 그때 PAT 만 새로 발급하면 됩니다.

수동 갱신이 필요할 때 (24시간 이상 지난 토큰만 가능):
```powershell
..\.venv\Scripts\python.exe get_token.py refresh --token <기존토큰>
```


> 토큰은 GitHub Secret에만 들어갑니다.

## 9. 게시 시각

| 시각(KST) | 채널 | cron (UTC) |
|---|---|---|
| 13:00 | 이메일 | `0 4 * * *` |
| 18:00 | 스레드 | `0 9 * * *` |
| 18:10 | 페이스북 | `10 9 * * *` |
| 18:20 | 인스타그램 | `20 9 * * *` |
| 매달 1일 12:00 | 인스타 토큰 갱신 | `0 3 1 * *` |

cron 은 UTC 기준입니다. 원하는 KST 시각에서 9시간을 빼면 됩니다.
세 채널이 20분 안에 몰려 있지만, 각 워크플로가 진행 기록을 푸시할 때
`git pull --rebase` 를 거치므로 서로 충돌하지 않습니다.
